# Mechanism：机制与关系

当主要理解任务是解释对象如何相互作用、结果如何产生及成立条件时使用。出现术语或公式本身不决定此 Profile。

本 Profile 只指导内容关系表达；内容取舍与展开程度服从本次所选模式，不要求补回该模式已省略的次要内容。

## 编辑重点

- 围绕核心问题组织必要对象、作用路径和结果，将定义放在首次使用处，依赖关系先于复杂推导。
- 区分输入、状态、作用、输出及反馈；仅在来源包含这些关系时展开，不强填系统框架。
- 保留改变机制成立范围的条件与反例；代表性推导或例子按所选模式取舍。
- 核心机制及适用边界就地呈现；作用路径图直接承担解释，按所选深度补充依据和细节。

## 可选表达

优先考虑 State / Relationship Map 表达作用、反馈或资源循环，Before → Trigger → After 表达状态变化。公式、正常段落和局部对照仍可承担推导；其他视觉语法按需要使用。

## 从文字说明到关系图：示例

假设来源已说明“工作上下文在窗口内，事实存在外部存储；模型通过工具检索事实，结果回到工作上下文，用于回答”。

- 弱表达：一段讲窗口，一段讲外部存储，再加一块底色复述读写机制；读者仍要自己拼出位置与流向。
- 更清楚：画出「窗口内的工作上下文」和「窗口外的事实存储」两个区域；从前者画出标有“工具检索”的请求箭头，从后者画回“相关事实”结果箭头，再由工作上下文连到“生成回答”。邻近文字只补充来源给出的用途与限制。

此例只展示已知的读取路径；来源没有写入、删除或失败分支时，不把它们补进图里。不要只画“记忆 → 智能体 → 更聪明”这类抽象标签链。

## 失真提醒

不将相关性、类比或假设转为确定因果；不凭熟悉的理论补齐来源缺失的对象、公式项或反馈路径。图中保留关系性质与条件，不能用抽象标签和箭头代替解释。
