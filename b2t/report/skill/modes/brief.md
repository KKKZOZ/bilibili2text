# 精简速览（brief）

仅在任务选择 `brief` 时读取。完整理解原始转写，独立编辑一份**大标题、清晰编号、视觉表达优先、有明确篇幅边界**的速览。读者应能从章节标题抓住主线，再读必要依据与条件。不先生成 Standard 再压缩，不把原视频逐章缩写成卡片长卷。

只读取 [Brief 模板](../assets/brief-report-template.html)，使用其内联 CSS 与 `brief-` 组件，不读取另一模式或其模板。公共来源准确性规则始终适用；公共完整解释要求仅适用于本模式选中的核心内容，不据此补回全部细节。

## 篇幅与文字密度：交付硬约束

- **正文目标 1600–2200 字，上限 2400 字**。统计所有 `.brief-section` 的可见文本（含标题、卡片、图表标签、条件与数字口径，去掉空白后逐字符计数）；题头来源、页尾及折叠来源说明不计。短来源可明显少于目标，不为凑字数补写。写完实际提取 HTML 文本计数，不能凭估计声明达标。
- **每个段落、条目、表格单元格或节点说明通常 1–3 行，最多 4 行**，以模板约 900px 桌面画布、18px 正文和所在组件实际宽度为准。窄卡片的额度比通栏少，不把通栏短段原样塞进窄卡。标题不计入说明行数，必要条件仍计入。
- **相邻独立正文最多两段，合计不超过 6 行**。两段之间插小标题、横线、空白、轻标签，或把段落改成列表，不算打断连续文字。图表或组件必须真正承载另一层信息关系，不能作为分隔符继续堆段落。
- **每个大章节的通栏叙述合计不超过 8 行**；其余必要信息由合适的小组件表达，但组件里的文字仍计入总预算。不能把一段长文拆成多个三行段落，也不能把长文塞入一张巨卡或许多小卡规避限制。
- 内容超出预算时，保留核心问题、关键判断、决定性条件与代表性依据，整项删除重复、辅助案例和细枝末节；不能删掉限定、单位、归属和关键因果。确实无法在上限内讲清时，说明超限原因，不能默默交付 Standard 篇幅。
- 不允许缩字号、CSS 截断、固定高度遮挡、强制换行或把正文藏入折叠区满足上述约束。题头导语控制在两句内，避免提前重复全文。

## 先形成主线，再写正文

1. 完整读完来源，确定读者最需要回答的核心问题。围绕回答过程组织少量大章节；章节数量随信息结构确定，不强凑数量或因果。每章只解决一个主要问题，标题简短、具体，连起来能说明整篇如何推进。
2. 先选核心判断、决定性依据和成立条件。保留主要主题、理解所需的解释和有代表性的依据，在篇幅预算内保留足以解释主线的内容。背景、过程和例子按对理解的贡献取舍；主要主题保留关键判断与条件即可，不能以“信息充分”为由逐项复述。
3. 同一事实、数字、机制或建议只展开一次。影响分析与个人应对合并重叠材料，图中已表达的关系不再逐项解释。事件先后对理解重要时，用带方向箭头与时间节点的时间轴表达，让文字依附节点；不把一组日期与事件排成纯编号段落墙。

新闻背景用开头短说明交代，不先展开一整节行情或术语课。写前判断“这项内容改变哪个核心答案”；答不出来就省略。篇幅通过取舍变短，不通过小字、窄列或高密度信息压缩变短。先分配整篇字数预算，再选择内容与组件。简洁来自信息分组与紧凑表达：先看一个小组件能否清楚承载关系，再决定是否需要短段解释；不能只留下段落与彩色卡片。

## 固定的阅读骨架

- 保留醒目的主标题、简短导语、完整来源与原有页尾。导语用一两句交代对象和核心问题，不列目录；副标题无新增含义时省略。
- 大章节使用 `.brief-section > h2`，模板自动显示 `01、02、03` 章节编号，作为阅读定位，不暗示因果或操作顺序。不要手工重复编号，不取消章节大标题。章内不再多层编号或堆叠小标题；同章确有不同子话题时，用一层具体小标题和分组容器明确各自范围，不把几个话题只串写在章标题里。
- **Brief 正文不显示时间戳**：不生成 `.section-time`，不在图表、章节旁或说明中另写来源时间。保留隐藏的 `data-source-units` 与页尾折叠来源说明，需要回查时依靠来源绑定。Standard 的章节时间戳规则不用于本模式。事件本身的日期或时间是内容，可显示在时间轴节点；这与视频来源时间戳不同。
- 每章围绕一个主要问题，将必要材料拆成易读的小单元。分支、变化、算例和观点边界优先用对应小组件直接表达，短段落补充上下文与不能图解的解释。组件替代相应文字，不在图前图后重复讲一遍；也不为显得丰富而机械轮换组件。
- 并列内容不必做成卡片；彩色卡片只强调核心判断或对照。保持白底、原有字体，卡片使用模板的明亮浅色：蓝 #dfefff、绿 #d8f5e7、珊瑚 #ffe2d8、紫 #eae3ff；黄色使用稍浅的 #fff5cc。不要自行降低饱和度、混灰或调暗；相同语义使用相同颜色，不以颜色暗示来源没有支持的优劣。

## 少量层级，避免小字

- 保持模板字号：主标题 38px、带编号章节标题 30px、卡片标题 22px、正文与必要说明 18px。来源字段和页尾可略小；正文、数字口径、条件、表格、图注与图内标签不能降为小字。
- 必要限定直接放在对应判断的句子或紧邻正文中，以同样字号阅读。不要把整段重要内容降为灰色小字旁注，也不要用左侧短标签加右侧长段落的形式挤出窄栏。
- 用自然正文交代归属与条件，不把编辑检查项展示给读者。标题已经说明“作者的看法”时，不再追加“作者经验观点”“适用范围：作者观点”等同义标签；不把“已有依据”“判断边界”“适用边界”作为反复出现的固定栏名。真实的期限、对象、前提与不确定性仍须就地保留，直接写入句子；来源未提供的免责声明不补写。
- 遵守公共文风规则，直接表达观点、推理与例子，默认去掉“作者认为”“他用……打比方”等转述引导语及叙述过程铺垫。观点的条件与不确定性直接写进句子，必要归属仅按公共规则保留，不用反复标注作者来区分观点与事实。
- 标题负责导航，正文只对关键判断或词语加粗。对于包含两行以上连续正文且有明确落点的章节，优先选一段，在原句内加粗一处短语提示关键判断或概念；其他解释保持普通字重。无合适落点时不强加，不要求每段都加粗。数字与对象、单位、基准一起读，不把每个数字放大成独立视觉焦点。
- 卡片解释通常一至两句，最多四行；必要限定与结论一起重组。超过时先删除非必要信息，不能拆成连续小段规避。不得 CSS 截断、固定高度遮挡、机械换行或缩字号。
- 主要靠留白、对齐和章节编号分组。默认不加满边框和分隔线；选定组件的细分支线、轻角线、结果标记与折角可以保留，一处组件只用一种主装饰。连线只表达来源支持的关系：方向关系可用箭头，共同主题下的归属关系用无箭头分支线；表格只在跨行比较比文字更清楚时使用。

## 组件按需使用

以下已选定表达是可按关系组合的工具，不设数量配额，不要求一篇用全。先确定需要表达的关系，再选择组件，不能先凑版面。用模板末尾的合成示例理解结构；交付时删除示例注释，替换真实来源内容与绑定。选择代号 A2/A3/B1/B3/B4 仅用于设计记录，不展示给报告读者。

| 表达 | 模板类 | 使用边界 |
|---|---|---|
| A2 条件分支 | `.brief-branch-group`、`.brief-branch-origin`、`.brief-branches > .brief-branch` | 同一工具、条件或决策的不同作用与边界；分支各有清楚标签，不把并列或可以同时成立的判断画成互斥选项 |
| A3 前后变化 | `.brief-change`、`.brief-change-value`、`.brief-change-result` | 同一口径下两个状态及其结果；对象、单位、基准就地保留，不画虚假比例或暗示未经证实的因果 |
| B1 留白卡 | `.brief-open-card`、`.brief-boundary` | 一个判断及其必要条件，用白底和轻角线聚拢；默认直接写短正文，需要区分具体内容时才用短标签；长解释先取舍，不挤成窄栏也不转移成正文墙 |
| B3 参数算例卡 | `.brief-case-card`、`.brief-case-params`、`.brief-case-result` | 参数和结果必须一起理解的算例；保留单位、条件与约数。与 A3 按实际重点二选一，不重复呈现同一例子 |
| B4 折角便签 | `.brief-fold-card`、`.brief-fold-scope` | 作者观点、经验或建议；归属说明一次，必要限定融入正文，`.brief-fold-scope` 仅在有值得单独强调的具体条件时使用，不必填；不作为随意追加的总结，也不把关键事实藏成脚注 |

新增的阅读结构同样按内容需要使用：

- **时间轴**：`.brief-timeline > li > .brief-time-body`，节点内用 `time` 写事件日期、`h3` 写转折、`p` 写必要说明。默认左侧纵轴向下，较短节点可加 `data-layout="alternating"` 使用中轴左右交替；均有贯穿的箭头与节点。日期顺序须真实，不把时间先后自动当作因果。曲线/折线只在路径本身有意义且仍容易跟读时局部绘制，不为装饰打乱阅读顺序。只保留改变判断的关键转折，每个节点说明最多三行，不用时间轴装入所有发言和会议经过。时间线里的内容不在相邻段落完整复述；操作步骤仍用 `.brief-flow`，不混淆操作与事件。
- **数字概览**：`.brief-facts > .brief-fact` 将关键数字封装在一个整体浅底容器中，数值和口径分层。同一行各项等宽；保留单位、对象和概率性质，不把零散粗体数值直接插在段落之间，不再重复一遍相同数据段。
- **观察与后续判断**：`.brief-watch > .brief-watch-item` 按实际变量分组；每项用具体短标题和一至两句正文，自然连接当前情况、条件与可能影响。默认直接在卡片内写 `p`，不加固定栏名；确有两个需要对照的方面时才用 `.brief-watch-body` 分区，`.brief-watch-label` 可省略，需要时写具体内容名称，不能照搬“已有依据—判断边界”等编辑术语，也不能为了凑两列拆句或编造结果。尾部多项展望、建议与限制先分组，不以长段落或长 bullet 列表收尾，也不把整段搬进单个色卡。每项保留核心判断和就地条件，单个说明区最多三行；其他展开按预算取舍，不能转移到相邻正文。
- **话题分组与并列维度**：先让读者看出每段属于哪个话题。`.brief-topic` 配 `.brief-topic-title` 标出同章子话题；两个短方面可用 `.brief-topic-pair`，较长解释保持单列，不能为了并排突破行数预算。同一主题下的短维度，用 `.brief-dimension-group` 的淡紫标题带和白底正文统领，再用 `.brief-dimensions > .brief-dimension` 展开；不要把每个短句做成独立通栏卡片，留下大片空白。模板根据实际子项数量自动布局，不设置 `data-columns`：两项两列、三项三列，保留无箭头分支线；四项自动 2×2，更多项按两列续排，隐藏横向树线和所有短竖线，标题与正文左对齐。不得将四项塞进三列形成 3+1，也不得在换行后留下孤立连线。不为凑列数增删内容；长文改用单列或其他合适结构。保留分支线时，横线端点、短竖线与各列标题中心必须对齐，线段连续相接；正文保持左对齐。共同标题带表示归组，正文不铺整块紫底；分支线只用于两、三项，不表示因果或先后。组内结论留在该组，不让它漂到下一话题前。
- **并排卡片对齐**：`.brief-pair` 使用等宽、拉伸至同一行最高内容的布局。同一行保持相同内边距与顶部对齐；一张多换一行时，另一张自然拉伸等高，不用删字、缩字、固定高度或隐藏内容来凑齐。

保留 `.brief-feature` 与 `.brief-pair > .brief-card` 作为简单强调/对照，短条目可用 `.brief-list`。复杂关系确需图示时用 `.brief-map`，操作先后用 `.brief-flow`，跨行比较用 `.brief-table`，不把它们当作必备模块。图表与卡片承载的正文也要完整可读；优先拆分信息关系，不靠缩字号或删除必要解释。辅助 `.brief-condition`、`.brief-note`、`.brief-caption` 与 `.brief-facts` 同样只按需使用。

### 表格列宽：保留完整短标签

短标签与长说明混排时，先为标签保留足够宽度，再给说明分配列宽和列间间距；不能把两字标签挤成逐字换行，也不能让相邻说明贴成一句。正文保持 18px，不靠删字或缩字解决。

仅在四列依次为「四字以内短标签、两字以内短标签、说明、说明」时，可使用模板的 `.brief-table-wrap > .brief-table[data-layout="labels"]`：列宽为 16% / 10% / 38% / 36%，短标签不拆行，两列说明之间留细分隔线。其他列数、较长标签或数字表按内容另定列宽，不机械套用。该结构窄屏保留局部横向滚动，外层区域保留可读名称及键盘焦点；代价是说明可能增加行数、窄屏需要滚动。生成后仍需在桌面检查实际文字长度及行数，不能将本例比例当作所有表格的通用规则。

## 不可压掉的事实边界

- 保留主体、说话人归属、成立条件、否定、因果方向、数字单位与基准以及“约”等口径。具体算例不泛化为任意条件成立的公式。
- 预测、经验、类比与作者观点保留其性质，不写成确定事实或已验证结果；标题和图同样遵守。遇到识别含混的非核心数字，省略该例而不猜测修复。
- 关键依据足以支持判断；可省略次要案例，一旦保留就带齐决定性条件。不能将限定统一挪到页尾或折叠区。
- `data-source-units` 逐个列出真实存在且实际支持内容的 ID，以空格分隔。禁止区间、通配符、自造 ID 或整篇 ID 替代逐处绑定；无原生 ID 时按公共规则建立逐段映射。ID 有效不代表语义准确。

## 交付前集中修订

先只读主标题和编号章节标题：能否看出整篇的核心问题和推进方向？再检查标题、标签与正文是否重复说明观点归属，或把编辑术语当作栏名；删去这些套话，保留实际条件。再读最密集处：是否仍有小字说明、过多局部标题、长段卡片、重复例子或非必要时间线？若仍像原视频逐章摘要，回到主线合并和取舍；若只有几段文字加色卡，检查应当转成分支、变化、算例或留白说明的关系。依据与解释服从总预算；既不能删成只有结论，也不能用大量组件包裹近乎完整的转写。

先实测总字数、单段行数、连续正文行数和每章叙述总行数，超限先修订再交付。静态检查无法测量真实行数时明确说明，不声称通过行数检查。再核对标题、关键数字、图中关系和建议的来源、归属与限定；确认没有正文时间戳。以约 900px 桌面查看顶部、复杂区与结尾，实际确认标题和编号醒目、正文说明可读、同排卡片等高、数字有整体容器、时间轴节点与箭头相连、尾部按话题分组、共同标题能统领子项、分支线连续且对齐子项标题中心，没有溢出或图文重叠。不以字数、图片高度或检查通过证明速览质量，不写未执行的检查声明。
